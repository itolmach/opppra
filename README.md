# Opera

A personal opera journal for iPhone and iPad: search the repertoire, keep
lists of what you want to see and what you have seen, and log each night at
the opera with ratings and notes.

**It ships through the App Store only.** There is no web version. Code is
staged in this repo on branches; what people get is the app.

## What is here

| | |
| --- | --- |
| `OperaApp/` | The SwiftUI app (iOS 16+). No Swift packages: networking is `URLSession` and `Codable` |
| `OperaApp/Config/Config.xcconfig` | The one config file: three public addresses, no secrets |
| `supabase/migrations/` | The schema, written once |
| `neon/migrations/` | The same schema for Neon; `0001`, `0003`, `0004` are generated by `scripts/port-to-neon.py` |
| `.github/workflows/` | `checks.yml`, `ios-build.yml`, `testflight.yml` |
| `NEON_SETUP.md` | How the app talks to the backend, and what works |
| `CLAUDE.md` | What a Claude session needs to know here |

The backend is [Neon](https://neon.com): Postgres behind its Data API, with
Managed Better Auth for accounts. Authorization is grants and row level
security in the database; the app holds no key. The catalogue (about 2,500
operas, with titles in several languages) is our own, built from MusicBrainz
and Wikidata by the scripts on the `opera` branch of `itolmach/TolmachevFamily`.

## How to run it

With a Mac: open `OperaApp.xcodeproj` and run. There is nothing to configure
and no package to resolve.

Without one: every push that touches the app is compiled by the `iOS build`
workflow, which is how the code is checked day to day.

## How it deploys

`testflight.yml`, started by hand from the Actions tab, archives the app,
signs it with Apple's cloud-managed signing and uploads it to TestFlight. It
needs three repository secrets from one App Store Connect API key (named at
the top of the workflow file) and an app record in App Store Connect. From
TestFlight, a build is submitted for review in App Store Connect.

"Live" means the build is visible in TestFlight or the App Store, not that a
run went green.

## Checks

Every push: property lists parse, the config addresses are whole, the Neon
migrations match their source, and nothing in the app still reaches for
Supabase. Pushes that touch the app also compile it for the simulator.

## What is left to a person

- Making the App Store Connect API key and putting its three values into this
  repo's secret settings.
- Creating the app record in App Store Connect, and everything on its page:
  name, screenshots, privacy answers, submitting for review.
- Adding the Apple provider to Neon Auth (Services ID, Team ID, Key ID and the
  `.p8` key go into Neon's console).
- The app icon: `Assets.xcassets/AppIcon` has a slot and no image, and an
  upload is refused without one.

## What does not work yet

- Photo upload on a log (needs Neon Object Storage and a small function to
  sign uploads).
- Productions, venues and performances: the tables are empty, and the app
  shows nothing there rather than failing.
- The playbill and favourite houses exist in the database but have no screen
  in the app.

Older notes in this repo (`QUICKSTART.md`, `RUN_NOW.md`, `OPEN_PROJECT.md`,
`FIX_*.md`, `TROUBLESHOOTING.md`, `HANDOFF.md`) predate the move to Neon and
describe a setup that no longer exists.
